# Changelog

All notable changes to the member app are documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Its own version stream: the backend and the console do not move in lockstep
with each other, and this app moves with neither.

## [Unreleased]

### Added

- **Tamil and English**, asked once on a first run and changeable afterwards
  from a toggle on the login and profile screens. 160 strings moved into
  `lib/l10n/app_{en,ta}.arb`; `flutter_localizations` brings Flutter's own
  Tamil with it, so the date picker and every built-in control follow without
  a string of ours.
  - The language screen writes `தமிழ்` and `English` each in its own script
    and translates neither, in either direction: the person who most needs
    that screen is the one who cannot read the other option.
  - The choice is read in `main()` **before** the first frame, so the app
    opens in the right language rather than repainting into it.
  - Stored in a new `SettingsStore`, shaped like `TokenStore`. It reuses
    `flutter_secure_storage` - not because a language code is secret, but
    because adding `shared_preferences` for one string would widen a
    dependency list the pubspec deliberately keeps short.
  - **Server messages stay English.** They are the API's own words, and a
    translation here would be a second copy of its vocabulary, drifting.
- **The association's emblems**, as a masthead on the login screen: FTTDDWA
  left, AITDWO right, the name between them. Each sits on a white disc,
  because both are artwork with white backgrounds and a bare one reads as a
  lit square against the dark theme.
- **The emblem as the launcher icon and the splash**, replacing the stock
  Flutter mark, generated by `flutter_launcher_icons` and
  `flutter_native_splash` from PNGs that `tool/make_brand_assets.dart`
  produces from the WebP artwork. Neither generator reads WebP, and no
  converter on a typical Windows box does either - the tool uses the pure-Dart
  `image` package so there is no native toolchain to install.
- `PublicSite.shortNameTamil`, which the server has always sent and nothing
  read until the masthead had a Tamil mode.

- **Tamil name fields refuse English letters**, and both dates are bounded: a
  date of birth must be at least 18 years ago, and a wedding date must fall
  between it and today. Both checks live in `shared/validation.dart`, mirroring
  the server's own rules.
  - The Tamil rule runs on **submit, never per keystroke**: Tamil is commonly
    typed on a transliteration keyboard, where Latin letters are the
    intermediate state before the Tamil is committed, so filtering input would
    break exactly the people the field exists for.
  - The wedding date is now **required once "Married" is ticked**. `DateField`
    is an `InputDecorator` rather than a `FormField`, so `Form.validate()`
    walks past it - the step checks both dates itself, as it already did for
    the date of birth alone.

- **The applicant's photo**, from the camera or the gallery, on step 1 of the
  application — where the console puts it. It uploads to
  `POST public/member/photo` on selection rather than on submit: the image
  dwarfs the rest of the form, and a failed submit should not mean taking the
  photo again. Downscaled to 1280px before sending, because a phone camera
  produces 4-8 MB and the server refuses anything over 2 MB. This supersedes
  the 1.0.0 omission below, which was accurate when there was no public upload
  route.
- A **Cancel** button on the application, and a confirmation before it discards
  anything typed. The form previously had no way out but the system back
  gesture.
- **`AppStatusColors`**, a `ThemeExtension` carrying the console's `--success`,
  `--warning` and `--info`. They have no slot in a Material `ColorScheme`, and
  as a theme extension dark mode resolves them without any widget asking which
  mode it is in.

### Changed

- **The membership-number field lost its `TN72001` placeholder.** The helper
  beneath it already says where to find the real number, which is the part
  that helps; a sample inside the box is one more thing to read past, and at a
  glance reads as a filled field.
- **The splash is white, not the header gradient.** The native splash Android
  draws before Flutter starts is white with the same emblem, so the gradient
  made every launch flash white then indigo. The gradient stays on the profile
  header, where nothing hands over to it.
- **Validation rules return a code, not a sentence.** `shared/validation.dart`
  has no `BuildContext` and could only ever have returned English. The screens
  turn a `DateProblem` into words; the tests assert on the code, which is also
  sturdier than matching prose.
- The app is **FTTDDWA** on the launcher and the iOS home screen, where it was
  the scaffold's "Membership".

- **The Aadhaar number is optional**, matching the server and the console. It
  was hard-required at exactly 12 digits, so an applicant without one could
  complete the web form and was stopped dead at step 1 here. A part-entered
  number is still rejected. A blank field is now **omitted** from the request
  rather than sent as `''`.
- **The theme is the console's**, not a seeded one: an explicit `ColorScheme`
  built from `console/src/app/globals.css` (indigo `#4F46E5`, sky `#0EA5E9`,
  slate neutrals, an 8px radius), flat bordered cards and filled inputs. The
  splash and the profile header carry the console's own header gradient. Fonts
  are untouched — `NotoSans` with `NotoSansTamil` as the **fallback**, which is
  the only arrangement that renders both scripts.
- The application's steps are **named and numbered** on a rail, with each
  step's fields in a card under a heading and a line of explanation, replacing
  a 4px progress bar that never said what was still to come. Moving between
  steps now scrolls back to the top — one scroll view serves all four, so
  somebody who filled step 1 to the bottom used to arrive at step 2 already
  past its heading.
- Helper and error text under a field **wrap** instead of ellipsizing. Both
  default to one line, which cut the Aadhaar field's explanation in half on a
  phone.
- **A fixed position is shown read-only** rather than as a one-item dropdown.
- **Registration closed and the association being unreachable now read
  differently.** `PublicSite.empty` has `registrationOpen: false`, so a timed
  out branding fetch silently hid Apply with nothing said; the login screen
  now distinguishes the two and offers a retry for the second.

### Fixed

- **The Android build works again on a machine whose pub cache is on another
  drive.** Kotlin's incremental cache stores paths relative to the project, so
  a plugin compiled out of `C:\…\Pub\Cache` cannot be expressed against a
  project on `D:` — Gradle fails with `Could not close incremental caches`,
  naming no drive. `kotlin.incremental=false` in
  `android/gradle.properties`, with the reasoning, is cheaper than relocating
  the whole cache. It first bit when `image_picker` became the app's only
  plugin with Kotlin sources.

### Removed

- `BilingualRow.monospace`. It set `fontFeatures: const []`, which selects no
  features and changed nothing, and nothing ever passed it.

- **The position is chosen for the applicant** when the association sets
  `memberRegister.positionId`. The server already narrows the list to that one
  row, so step 3 would otherwise make someone open a one-item picker to satisfy
  a field they were never given a decision about. Falls back to auto-selecting
  whenever exactly one position is offered, so it behaves the same way for an
  association that simply has one.
- `PublicSite.fixedPositionId`, matching the new field on
  `GET public/member/site`.

## [1.0.0] - 2026-11-25

First release. A native client for the member portal, covering the same three
things the web portal does: sign in, apply for membership, and see your own
record and card.

### Added

- **Login** with a membership number and password, the same identity the web
  portal uses. Server messages are shown verbatim — "This membership is
  suspended. Please contact the association." is already written for the person
  reading it, and mapping status codes to copy of our own would only lose that.

- **A four-step application**: identity, contact and sign-in, association, and
  location. It collects everything `tenant_member_applications` holds, because
  that is the point of the table — the applicant supplies their details once
  and approval is a copy rather than a second interview.
  - All six lookup lists arrive in one `options` call and cascade in memory, so
    changing a state does not cost a round trip.
  - The **RTO cascades off the DISTRICT**, not the taluk above it, and the
    payload's parent key for it is `tenantDistrictId` where every other list
    uses the short form. Reading the wrong key yields an empty picker and no
    error at all, so there is a test pinning it.
  - Submitting creates an APPLICATION, never a member. The screen says the
    membership number is issued on approval, so it cannot be mistaken for a
    welcome.

- **A profile screen** showing the member's own record in both scripts, with a
  card panel: issue number, expiry, an expired warning, and a PDF download.
  Nothing on it is editable, because no endpoint exists for a member to edit
  their own record.

- **A splash screen** that restores a stored session and fetches the
  association's branding, then leaves. It asks for nothing — everything it
  needs is in `.env`.

### How it knows which association it serves

The API resolves the business from the **hostname** and accepts no business id
in any request body. An app has no hostname, which looks like a dead end.

It is not, because `SiteService.hostOf` reads `Origin` before
`X-Forwarded-Host` before `Host`. The app sends
`Origin: https://<APP_ASSOCIATION_HOST>` and resolution works unchanged, with
no backend change and the business still never coming from a body field.

Consequences worth stating:

- **One build serves one association.** `flutter_dotenv` bundles `.env` as an
  asset, so its values are build-time. There is deliberately no public endpoint
  listing associations, so a picker is not possible — claiming a hostname is a
  trust boundary.
- **Android and iOS only.** In a browser `Origin` is set by the browser and
  cannot be overridden, so a web build could only ever address the association
  serving it.

### Deliberate omissions

- **No passport photo on registration.** `system/uploads` and `tenant/uploads`
  are both behind staff guards and there is no public upload route, so
  `passportPhotoPath` is left unset and staff attach one at approval. Adding a
  public upload endpoint is a backend decision and a new attack surface.
  *(That decision was since taken: see Unreleased.)*
- **No password change**, though `POST member/auth/password` exists.
- **No state-management package and no form library**, matching the console's
  house style: one `ChangeNotifier` for the session, and plain `setState` with
  one state object and a `saving` flag per screen.

### Notes

- The refresh token is held in the platform keystore via
  `flutter_secure_storage`, not `SharedPreferences`: it is a bearer credential
  good for seven days.
- Refresh **rotates** — the presented token is revoked as the new one is issued
  — so the client replaces what it stored, and the HTTP client refreshes at
  most once per request to avoid a second attempt presenting a token the first
  just revoked.
- The splash never blocks on the network: the branding fetch runs under a 3s
  timeout and the app proceeds without it, because a member can still sign in
  when a logo cannot be loaded.
- `csrfToken` from the login response is discarded. The CSRF guards are not
  global — they sit on four staff handlers — and member routes set no cookies.
- `INTERNET` is declared in the **main** Android manifest, not only the debug
  one Flutter generates. An app that is nothing but API calls would otherwise
  ship with no network access and nothing in development would reveal it.
- Cleartext HTTP is permitted only by a **debug-only** network security config
  naming `10.0.2.2`, `localhost` and `127.0.0.1`. A blanket
  `usesCleartextTraffic` would also permit cleartext to real hosts.
- Tamil renders through `NotoSans` with `NotoSansTamil` as a **fallback**, the
  same pair the backend uses to print a card. Tamil cannot be the primary
  family: `NotoSansTamil` has no Latin glyphs, so a membership number like
  `TN72001` would render as boxes.
